## Simulation and coverage

Fresh browser contexts install request routing before navigation and block service workers so they cannot bypass interception. Routing disables the HTTP cache. Each request is evaluated against the same test-only rules, with no unconditional allowlist that could hide a collision on a critical route.

| Profile | Behavior | Journey widths |
| --- | --- | --- |
| `observe` | Unblocked control with identical instrumentation | 1440, 375 px |
| `tracking-only` | Abort known tracker hosts, bounded analytics/telemetry/tracking/ad/beacon/collect/pixel path tokens, and ping resources | 1440, 375 px |
| `third-party-and-tracking` | Tracker rules plus every request outside the preview origin | 1440, 375, 320 px |
| `font-files` | Tracker rules plus font resources; external CSS remains allowed | 1440, 375 px |

Every browser now runs 16 cases: nine complete journeys, two native/no-JavaScript cases (control and third-party blocking), two delayed-hydration cases (control and third-party blocking), one blocked-transport retry, one inventory, and one rules/classification test. No retries, expected-failure markings or test skips were added.

Complete journeys check homepage usability and horizontal geometry; all four header anchors and sticky offsets; mobile menu keyboard opening, Escape/focus restoration and closing after navigation; independent FAQs and technical disclosure; service CTA/preselection; empty and malformed-email validation; optional disclosure toggles and retained notes/provider state; all three authority labels with at least 44 px height and actual click/check behavior; successful single-POST demo submission; confirmation copy, reload and footer navigation. Populated optional forms run at desktop/mobile widths; the 320 px journey keeps optional fields closed.

The 375 px transport test deliberately fails exactly the first submission POST while third-party blocking remains active, verifies retained values and inline error focus, then retries successfully with exactly two POSTs. This injected critical-path failure is recorded separately from privacy rules. Native submissions at 320 px exercise authoritative validation, retained required/optional values, correction and confirmation with JavaScript disabled.

After releasing scripts it requires hydrated conditional content, edits another field, verifies the entire early draft and provider removal/restoration, then reaches confirmation through exactly one POST. Scripts are delayed, not aborted; this timing fault is separate from the optional-resource blocking profile.

Twenty-seven full-page Axe analyses run with WCAG 2 A/AA, 2.1 AA and 2.2 AA tags and no disabled rules. They report zero violations; incomplete results remain recorded for manual review. Fifteen blocked-font checks confirm no loaded Inter face and identical measured text widths for `Inter, Arial, sans-serif` and `Arial, sans-serif`. ## Manual smoke checklist and remaining limits

On an isolated demo-enabled preview, repeat with real Ghostery, uBlock Origin and AdGuard in browsers that support them. Keep the extension enabled; record browser/extension versions, active filter lists and settings. Use only synthetic data.

1. Hard-reload the homepage with the blocker active and inspect its request log/DevTools. Record actual blocked URLs; default lists may not block Google Fonts. Separately enable external-font blocking or explicit font-domain rules and verify readable Turkish text without overflow at desktop and 320–375 px.
2. Follow each header anchor, open/close the mobile menu with keyboard and Escape, expand the technical disclosure and multiple FAQs, then use a service CTA to reach the preselected form.
3. Submit empty and malformed-email values. Verify visible associated errors and retained entries. Open/close optional fields, switch protection choices and check retained provider/notes values. On a throttled reload, start typing before scripts finish loading; confirm the draft survives the next edit after hydration.
4. Submit valid synthetic values and reach confirmation; reload, follow footer links and use Back/Forward. Confirm the page explains that no test started.
5. In a separate retry check, block only the submission POST temporarily using a method-aware development proxy/tool. Verify retained values and inline failure, remove that fault while leaving the privacy extension active, and retry successfully. Do not use a path-only rule that also blocks the form document.
6. Repeat native form validation/correction with JavaScript disabled. Inspect console/network logs: expected optional-resource blocking may be visible; uncaught application errors, failed first-party assets/navigation or lost form state are failures. Save logs/screenshots for any discrepancy.

Actual extension filter engines, cosmetic rules, scriptlets, browser tracking prevention, extension interactions and future list revisions are outside request-abort simulation coverage. Native Safari/VoiceOver and actual mobile hardware remain unverified. The existing Windows WebKit Tab-to-links limitation is documented in the earlier QA report and is not resolved by this pass.

Production release still requires the previously documented durable submission backend, operational safeguards, finalized privacy/operator details and a decision on external fonts. Demo confirmation is not proof of stored/delivered data. This pass does not authorize a public launch or test execution.
